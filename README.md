# منصة سوبرسيل لإدخال ودمج تقارير خدمة العملاء (متعددة المكاتب بالأدوار)

نظام ويب كامل بقاعدة بيانات حقيقية، يدير عدة مكاتب/فروع، كل مكتب له موظفوه ومديره الخاص،
مع فريق متابعة بصلاحية قراءة فقط على مكاتب محددة.

## الأدوار الأربعة

| الدور | الصلاحيات |
|---|---|
| **المدير العام** (super_admin) | ينشئ المكاتب، ينشئ حسابات مديري المكاتب وفريق المتابعة، يحدد أي المكاتب يراها كل عضو متابعة |
| **مدير المكتب** (office_admin) | ينشئ ويدير حسابات موظفي مكتبه فقط، يدخل بيانات، يرى الدمج اللحظي لمكتبه، يعدّل أي معاملة داخل مكتبه، يصدّر Excel |
| **الموظف** (employee) | يدخل بياناته الخاصة فقط، يعدّل/يحذف معاملاته هو فقط، يرى الدمج اللحظي لكل مكتبه (قراءة)، يصدّر Excel |
| **فريق المتابعة** (monitor) | قراءة فقط، فقط للمكاتب التي يحددها له المدير العام، لا يمكنه الإضافة أو التعديل أو الحذف إطلاقاً |

كل مستخدم (بكل الأدوار) له اسم مستخدم وكلمة سر خاصة به، مرتبطة باسمه الكامل الذي يظهر تلقائياً
كـ"اسم الموظف" في كل معاملة يدخلها — فلا داعي لكتابة الاسم يدوياً في كل مرة، ويستحيل انتحال شخصية
موظف آخر.

## التركيب

يتطلب [Node.js](https://nodejs.org) نسخة 22.5 أو أحدث (تحتوي دعم SQLite المدمج، فلا حاجة لأي
حزمة قاعدة بيانات خارجية تحتاج تصريف).

```bash
cd supercell-ftth-platform
npm install
```

## أول تشغيل — احصل على حساب المدير العام

```bash
npm start
```

في أول تشغيل فقط، يطبع السيرفر في الطرفية اسم مستخدم وكلمة سر مؤقتة لحساب "المدير العام":

```
اسم المستخدم: admin
كلمة السر المؤقتة: xxxxxxxx
```

**سجّل هذه الكلمة فوراً — لن تظهر مرة أخرى.** بعد أول دخول، غيّرها فوراً من داخل النظام
(زر تغيير كلمة السر، أو عبر `POST /api/auth/change-password`).

## الإعداد الأولي المقترح (بالترتيب)

1. سجّل دخول كـ `admin`، غيّر كلمة السر.
2. من تبويب "المكاتب": أنشئ مكتباً لكل شوب/فرع (مثال: Samarra Shop).
3. من تبويب "المستخدمون": أنشئ حساب "مدير مكتب" لكل مكتب، وحساب "فريق متابعة" واحد أو أكثر،
   وحدد لكل عضو متابعة أي المكاتب يُسمح له برؤيتها.
4. سلّم بيانات دخول كل مدير مكتب له، ليقوم هو بإنشاء حسابات موظفيه من تبويب "الموظفون" الخاص به.

## متغيرات البيئة (مهم جداً للأمان)

```bash
JWT_SECRET="اكتب-هنا-نص-عشوائي-طويل-جداً-32-حرف-على-الأقل"
NODE_ENV=production
PORT=3000
npm start
```

- **JWT_SECRET**: إذا لم يُعيّن، يستخدم النظام مفتاحاً عشوائياً مؤقتاً، ما يعني إلغاء كل جلسات
  الدخول عند كل إعادة تشغيل. عيّنه مرة واحدة وثابتة لبيئة الإنتاج.
- **NODE_ENV=production**: يفعّل خاصية `secure` على كوكي الجلسة (لا يُرسل إلا عبر HTTPS).
  فعّله فقط إذا كان الموقع يعمل خلف HTTPS فعلياً، وإلا لن يستطيع أحد تسجيل الدخول.

## تشغيل دائم (pm2)

```bash
npm install -g pm2
JWT_SECRET="..." pm2 start server.js --name supercell-platform
pm2 save
pm2 startup
```

## الأمان — ما هو مطبّق فعلاً في الكود

- **تشفير كلمات السر**: bcrypt، لا تُخزَّن أو تُعرض كلمات السر كنص صريح أبداً.
- **جلسات JWT في كوكي httpOnly**: لا يمكن لجافاسكربت في المتصفح قراءتها (حماية من XSS).
- **عزل بيانات كل مكتب**: كل استعلام يُقيَّد تلقائياً بـ `office_id` المستخرج من رمز الجلسة نفسه،
  وليس مما يرسله المتصفح — موظف مكتب لا يمكنه ولو بالتلاعب برؤية بيانات مكتب آخر.
- **صلاحيات فريق المتابعة**: تُتحقق من جدول ربط مخصص (`monitor_access`) في كل طلب، وليس مرة واحدة عند الدخول.
- **حماية من تخمين كلمة السر**: قفل مؤقت (5 دقائق) بعد 5 محاولات دخول فاشلة لنفس اسم المستخدم من نفس الجهاز.
- **الموظف يعدّل معاملاته فقط**؛ مدير المكتب يمكنه تعديل أي معاملة داخل مكتبه فقط (مختبر فعلياً).

## الأمان — ما يحتاج قراراً من فريق IT

- **HTTPS**: هذا الكود لا يشفّر الاتصال بنفسه. ضعه خلف reverse proxy (Nginx/IIS) بشهادة SSL
  داخلية، خصوصاً لأن كلمات السر تُرسل عبر الشبكة عند كل تسجيل دخول.
- **نسخ احتياطي**: ملف `data/platform.db` هو قاعدة البيانات بالكامل. انسخه دورياً لمكان آمن منفصل.
- **الوصول للسيرفر نفسه**: تأكد أن مجلد `data/` غير قابل للوصول من الشبكة العامة (السيرفر لا يعرضه
  كملف ثابت، لكن يُفضّل تقييد صلاحيات نظام الملفات أيضاً).

## بنية المشروع

- `server.js` — كل مسارات API، مقسّمة حسب الدور
- `auth.js` — تشفير كلمات السر، توليد/التحقق من JWT، الصلاحيات، حماية تخمين كلمة السر
- `db.js` — الجداول (offices, users, monitor_access, entries) وإنشاء حساب المدير العام الأول
- `stats.js` — حساب إحصائيات التفعيل/التنصيب/الصيانة وحالات الطلبات
- `public/index.html` — الواجهة الكاملة (تسجيل دخول + 4 لوحات حسب الدور + إحصائيات بيانية)

## تصدير Excel

مطابق تماماً لترتيب أعمدة ملف "Daily Report" الرسمي المعتمد لديكم، جاهز للصق المباشر فيه —
بما فيها الأعمدة المحسوبة تلقائياً (Day, Month - Text, Month - Year) من التاريخ فقط.

## الهوية البصرية

صُممت الواجهة بألوان كمّلية (كحلي/تركواز) تعكس هوية شركة اتصالات/ألياف ضوئية احترافية، بما أنه
لم تُرفق لي ملفات هوية بصرية رسمية (شعار/ألوان دقيقة) لشركة سوبرسيل. إذا زوّدتموني بالشعار
والألوان الرسمية، يمكن تطبيقها مباشرة على نفس الواجهة دون أي تعديل هيكلي.
